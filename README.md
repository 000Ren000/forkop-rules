# forkop-rules — менеджер доменов Forkop

CLI `domains` редактирует списки в этом репозитории, создаёт коммит только списков,
публикует текущую ветку и инициирует штатное обновление правил на OpenWrt.
Интерфейс и сообщения — на русском языке. Без аргументов открывается меню.

## Требования и установка

- Node.js LTS, версия не ниже 22.12.0; локально проверено на Node.js 22.12.0.
- Git с настроенными именем/почтой и доступом к существующему GitHub remote.
- OpenSSH `ssh-keygen` в PATH и существующий `known_hosts`.
- На роутере — Forkop 2.0 с его штатным ядром и настроенным Clash API.
- Доступ компьютера к роутеру по LAN/VPN и к GitHub/Raw. Проброс SSH в интернет не нужен.

В уже клонированной директории:

```bash
npm ci --ignore-scripts --omit=optional
npm run domains -- help
npm run domains -- list
npm run domains -- check
npm run domains -- sync --dry-run
```

Для короткой команды установите локальную ссылку и запускайте её из этого
репозитория или его поддиректории:

```bash
npm link
domains help
domains
```

Единственная прямая зависимость — `ssh2`. Меню, скрытый ввод, конфигурация и тесты
реализованы средствами Node.js. `npm link` регистрирует команду на вашем компьютере;
во время разработки глобальная регистрация не выполнялась.

## Конфигурация

Без локальных файлов используются значения из `config.example.json`. Для изменения:

```bash
cp config.example.json config.json
cp .env.example .env
chmod 600 config.json .env
```

В PowerShell вместо `cp` можно использовать `Copy-Item`; доступ к `.env` ограничьте
правами Windows. Не помещайте пароль в аргументы команд или `config.json`.
В `.env.example` пароль пустой. `.env`, его локальные варианты, `config.json`,
`node_modules` и служебная `.domains/` исключены из Git.

Приоритет: переменные процесса → `.env` → `config.json` → `config.example.json`.
Поддерживаются `ROUTER_HOST`, `ROUTER_PORT`, `ROUTER_USER`, `ROUTER_AUTH`,
`ROUTER_PASSWORD`, `ROUTER_SSH_KEY`, `ROUTER_KEY_PASSPHRASE`, `ROUTER_KNOWN_HOSTS`,
`GITHUB_REMOTE`, `GITHUB_BRANCH`. Пустой пароль приводит к скрытому интерактивному
запросу непосредственно перед SSH. В CI/перенаправленном stdin секрет должен быть
предоставлен окружением либо нужно использовать ключ/агент.

Основные настройки:

| Поле | Значение и поведение |
| --- | --- |
| `router.host/port/username` | `192.168.0.1`, `22`, `root` в примере; меняются локально |
| `router.auth` | `password`, `key` или `agent` |
| `router.sshKey` | Путь к приватному ключу; `~` раскрывается |
| `router.knownHosts` | Существующий `~/.ssh/known_hosts`; проверка обязательна |
| `github.remote` | `origin`; существующий remote не изменяется |
| `github.branch` | `auto` — текущая ветка; явное значение обязано совпадать с ней |
| `domains.file` | `auto` — определить реальный список; явный путь относительно корня |
| `domains.files` | Необязательный массив конкретных `.lst`, если нужно ограничить управление |
| `domains.autoSync` | `true` — синхронизация после изменения |
| `domains.sort` | `false` — сохранять порядок; при `true` сортируются доменные записи при добавлении |
| `forkop.updateCommand` | `auto` — определить команду по `forkop help` |
| `forkop.retryCount` | До 3 попыток по умолчанию, максимум 10 |
| `forkop.retryDelayMs` | Интервал 2000 мс по умолчанию |
| `forkop.timeoutMs` | Таймаут одной удалённой команды, 120000 мс |
| `forkop.rawTimeoutMs` | Таймаут одной проверки Raw, 15000 мс |
| `forkop.verifyTimeoutMs` | Таймаут чтения API через SSH, 20000 мс |

Автопоиск использует отслеживаемые и неигнорируемые неотслеживаемые `.lst` внутри
репозитория. При нескольких доменных файлах для добавления нужен `--file` либо
`domains.file`. IP-список автоматически не выбирается как доменный. Явный `--file`
ограничивает операцию и последующую синхронизацию одним существующим списком.

## SSH и подготовка Forkop 2.0

Пароль из прежней переписки в этой среде отсутствует и в приложение не включён.
При `router.auth=password` он запрашивается без отображения символов или читается
из `ROUTER_PASSWORD`. Приватный ключ применяется при `router.auth=key`;
зашифрованный ключ использует `ROUTER_KEY_PASSPHRASE`. Режим `agent` использует
`SSH_AUTH_SOCK`. Настройки `~/.ssh/config`, ProxyJump и host certificates этим
SSH-клиентом автоматически не импортируются; адрес/порт/ключ задаются явно.

Неизвестный, изменившийся или отозванный host key блокирует соединение до передачи
пароля. Поиск выполняет `ssh-keygen -F`, включая hashed known_hosts и `[host]:port`.
Автоматического доверия ключам и изменения known_hosts нет. Если ключ ещё не внесён,
сверьте fingerprint через доверенный канал/консоль роутера и самостоятельно выполните
обычное первое подключение OpenSSH с проверкой ключа. Не используйте
`StrictHostKeyChecking=no`. Для RSA используются подписи SHA-2.

После вашего обновления до Forkop 2.0 убедитесь в LuCI, что указанный выше Raw URL
подключён к наборам правил нужной секции, и примените настройки. Новая версия
поддерживает plain-text списки с `format: auto`; миграция переносит прежние
`domain_ip_lists` в наборы правил. CLI проверяет точный URL в рабочей конфигурации
и наличие соответствующего provider в запущенном ядре. URL другой ветки или ссылка
на страницу GitHub вместо Raw не подходят.

Контроллер ядра должен быть доступен через loopback самого роутера. Для чтения его
состояния нужен SSH TCP forwarding к `127.0.0.1:<порт API>`. Публичный порт API и
локальный слушающий туннель не создаются. Клиент читает `forkop.settings.config_path`
и рабочий JSON только в память; секрет API не выводится и не сохраняется.
Если конфигурация или forwarding недоступны, подтверждение применения завершается ошибкой.

Проверки с реальным подключением (запускайте после подготовки роутера):

```bash
domains ssh-check
domains status
```

Без подключения:

```bash
domains status --offline
domains sync --dry-run
```

## Использование

```bash
domains add example.com
domains add google.com youtube.com github.com
domains add example.com --no-sync
domains add example.com --file custom.lst --no-sync
domains remove example.com
domains remove google.com youtube.com --no-sync
domains list
domains search GOOGLE
domains check
domains sync
domains sync --file custom.lst
domains sync --dry-run
domains status
domains help
```

`custom.lst` должен уже существовать. Добавление и удаление принимают несколько
доменов. Новые значения приводятся к нижнему регистру; IDN преобразуется в ASCII
(Punycode), завершающая DNS-точка убирается. URL, маски, порты, IP вместо домена,
подчёркивания и некорректные метки отклоняются. Пакет валидируется до записи.
При добавлении проверяются дубликаты во всех управляемых доменных списках.
Повторное добавление не создаёт коммит и не запускает синхронизацию.

Без `--file` удаление ищет все управляемые списки и удаляет все точные вхождения
имени; дочерние домены и другие правила сохраняются. Если имени нет, выводится
сообщение. IP/CIDR редактируются вручную; CLI проверяет их и синхронизирует вместе
с доменными списками.

Поддерживаемый переносимый `.lst`: UTF-8 без BOM, домен либо IPv4/IPv6/CIDR на
строку, полнострочные комментарии `#`, пустые строки. `check` сообщает пустые строки
как информацию, комментарии пропускает, ошибки и дубликаты блокируют sync.
Inline-комментарии, регулярные выражения, Adblock/hosts/Clash YAML и бинарные `.srs`
в этом редакторе не поддерживаются. Исходные комментарии, порядок и окончания LF/CRLF
сохраняются, включая отсутствие финального перевода строки. Файлы записываются
атомарной заменой; символьные ссылки и выход за пределы репозитория запрещены.

## Что делает синхронизация

1. Берёт эксклюзивный `.domains/sync.lock`; проверяет списки и состояние Git.
2. Проверяет текущую ветку, незавершённые Git-операции и remote. Чужие staged
   изменения сохраняются; частично staged список требует ручного согласования.
3. Читает удалённый HEAD, получает его объекты через fetch и проверяет, что удалённая
   история является предком локальной. Автоматических merge/rebase нет.
4. При наличии изменений добавляет только конкретные `.lst` и выполняет
   `git commit --only` с сообщением `Update Forkop domain lists`.
5. Проверяет, что коммит содержит именно проверенные blobs, с учётом Git filters
   и `core.autocrlf`, затем делает обычный push текущей ветки. Уже существующие
   локальные коммиты этой ветки также будут опубликованы; история не переписывается.
6. Сверяет удалённый HEAD после push. Если публикация не подтверждена, SSH не начинается.
7. Ждёт точного содержимого опубликованных blobs на используемых Raw URL с ограниченным
   числом попыток. Сравнивает SHA-256; cache-buster к URL не добавляется.
8. Подключается по SSH с проверкой host key и определяет штатную команду по help.
9. Для Forkop 2.0 выполняет `forkop clash_api PUT /providers/rules`, как штатное
   обновление всех rule providers. Проверяет SSH exit code и вложенный HTTP status.
10. Читает `/providers/rules` через защищённый SSH-транспорт. Для изменённых файлов
    требует увеличения `revision` соответствующих активных providers. Для ручного
    повтора неизменённых списков допускает увеличение `updatedAt` после HTTP 304.
    Повторно сверяет Raw и сохраняет результат в `.domains/last-sync.json`.

Это подтверждает публикацию и установку набора правил работающим ядром. API ядра
не экспортирует полный список доменов: проверка не является побайтовым чтением
доменных правил из памяти или проверкой реального VPN-трафика. Отдельный тест
доступа к сайту может зависеть от DNS-кэша, устройства и остальных правил секций.

При ручном `sync` без локальных изменений push и проверка публикации всё равно
выполняются, после чего инициируется обновление роутера. Если в репозитории есть
другие отключённые/неподключённые `.lst`, ограничьте `domains.files` либо `--file`:
все синхронизируемые файлы должны иметь подтверждаемую привязку на роутере.

`forkop.updateCommand` можно явно задать как `forkop clash_api PUT /providers/rules`
или `forkop list_update`; произвольные shell-команды запрещены. Для 1.x оставлен
адаптер `list_update`, проверяющий привязки UCI и JSON-списки в `/tmp/sing-box/rulesets`.
Он консервативно завершится ошибкой при другой структуре runtime или невозможности
подтвердить содержимое. Основной сценарий этой версии CLI — Forkop 2.0.

Программа не обновляет пакеты, Forkop и ядро, не редактирует sing-box/UCI, не
выполняет дополнительный restart/reload. Применение выполняет штатный механизм
Forkop. `git add .`, force push, reset и изменение remote не используются.

## Диагностика и восстановление

| Сообщение | Действие |
| --- | --- |
| Ошибка авторизации GitHub | Проверьте ключ/агент для SSH remote или Git credential helper; пароль роутера к GitHub не относится |
| Удалённая ветка содержит новые коммиты / конфликт | Согласуйте ветки вручную, затем повторите `domains sync` |
| Частично staged список | Согласуйте рабочую версию и индекс этого списка вручную |
| Файл отсутствует / неоднозначный выбор | Укажите существующий `--file` либо `domains.file` |
| SSH host key неизвестен/изменился | Сверьте fingerprint и исправьте trusted known_hosts вручную |
| Неправильный пароль/ключ | Исправьте `.env`, используйте скрытый запрос либо проверьте ключ на роутере |
| Таймаут/обрыв SSH | Проверьте LAN/VPN; команда на роутере могла продолжить работу, не запускайте бесконтрольные повторы |
| Forkop/команда не найдены | Проверьте установку и `forkop help`; приложение ничего не переустанавливает |
| Список не подключён | Добавьте точный Raw URL в нужную секцию LuCI и примените настройки |
| Raw возвращает старую версию | Подождите обновления GitHub CDN и выполните `domains sync`; проверьте публичную доступность Raw |
| HTTP 503 / ошибка обновления | Посмотрите журнал Forkop в LuCI; возможна ошибка любого обновляемого provider |
| Применение не подтверждено | Проверьте API ядра, соответствие URL/ветки и журнал; успех не был объявлен |
| Другая операция уже выполняется | Дождитесь окончания; после аварии проверьте процессы и только затем удалите `.domains/sync.lock` |

Ошибки CLI возвращают ненулевой exit code. После ошибки публикации или роутера
локальное изменение сохраняется. Повторяйте `domains sync`: повторный `add` уже
существующего домена не запускает sync. После ошибки SSH успешный Git-коммит и push
не откатываются. Сохранённые pending-файлы и исходные revision позволяют продолжить
подтверждение того же коммита после прерывания. Служебное состояние и логи не содержат
паролей или секрета API.

Приватный GitHub-репозиторий с закрытым Raw требует отдельной схемы публикации:
эта версия использует публичные Raw URL без токенов. Не добавляйте токены в URL.
Предполагается один одинаковый fetch/push URL remote и существующая удалённая ветка.
Защита от параллельных операций действует для процессов `domains` в этой рабочей
директории; внешние редакторы и ручные команды Git должны завершиться до sync.

## Проверки и устройство проекта

```bash

```

Тесты используют временные файлы, mock Git/SSH/Forkop и локальный HTTP-стенд для
проверки SSH-транспорта. Настоящие GitHub и роутер не используются; Git-репозитории
в тестах не создаются. Проверяются валидация, IDN, пакетные операции, поиск,
сохранение формата, выбор файлов, дубликаты, ошибки, lock, dry-run, порядок
