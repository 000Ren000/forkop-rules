# Результат разработки

Дата: 28.10.2026.

Разработано приложение `domains` на Node.js (ES Modules) в существующем
репозитории. Реализованы add/remove/list/search/check/sync/status/help,
ssh-check и интерактивное меню. Есть пакетные операции, --file, --no-sync,
--dry-run, --offline, локальная конфигурация и скрытый ввод пароля.

Исходное состояние: чистая ветка main, HEAD
`a472e8853eb8afc33429ce2e9425826bf7ae8e79`, remote origin
`git@github.com:000Ren000/forkop-rules.git`. Изначально присутствовали README.md
и domains.lst; посторонних staged/unstaged/untracked изменений не было.
Список domains.lst содержит прежние 10 доменов и не изменялся.

С учётом решения пользователя перейти на Forkop 2.0 основной механизм обновления —
`forkop clash_api PUT /providers/rules`. Возможность проверяется по help;
подключение списка — по точному Raw URL рабочего rule set. Успех требует проверки
публикации, SHA-256 Raw и изменения revision активного provider. Повтор неизменённых
списков допускает updatedAt при HTTP 304. Проверка API идёт через SSH к loopback.
Дополнительных перезапусков sing-box и правок конфигурации роутера нет.

Для Git используются конкретные пути и commit --only. Чужие записи индекса не
включаются; частично staged список и незавершённые Git-операции блокируют sync.
История/remote не меняются; обычный push текущей ветки публикует и уже существующие
локальные коммиты. Lock охватывает редактирование и синхронизацию. Проверенное
содержимое сопоставляется с Git blobs с учётом core.autocrlf.

Проверки:

- Автоматические тесты: 84 passed, 0 failed; Git/SSH заменены тестовыми адаптерами.
- Синтаксис: 23 JS-файла, ошибок нет.
- Локально выполнены list, search OPENAI, check, sync --dry-run, status --offline.
- check: один список, 10 доменов, 0 ошибок.
- git diff --check: без ошибок; domains.lst совпадает с исходным HEAD.
- git check-ignore подтвердил исключение .env, config.json, .domains и node_modules.
- Установка зависимости: npm сообщил 0 vulnerabilities.

Не выполнялись реальные SSH-вызовы, git push, обновление Forkop, изменение UCI,
установка/обновление пакетов OpenWrt, изменение sing-box и глобальный npm link.
Пароль из прежней переписки в доступной среде отсутствует: приложение запросит его
скрыто при реальном подключении либо использует локальный .env/ключ/агент.

Живой сквозной сценарий с установленным Forkop 2.0 ещё требует отдельного разрешения
пользователя. Поддержка Linux предусмотрена кодом, но проверки проведены на Windows
с Node.js 22.12.0. Полный экспорт доменных правил из памяти ядра отсутствует в API;
подтверждение основано на Raw и revision/updatedAt, без проверки реального трафика.
Подготовка known_hosts, подключение Raw URL в LuCI и SSH forwarding к loopback API
описаны в README.md. Для Forkop 1.x есть консервативный адаптер по JSON runtime;
основной поддерживаемый сценарий — 2.0.

Оформляется один локальный коммит приложения, примеров настроек, тестов,
README и этого отчёта. Публикация не выполняется.
